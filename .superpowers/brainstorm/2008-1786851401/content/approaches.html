Three ways to build the review queue

All three hold cases before the Embassy sees them. The difference is how much help the admin gets.

A

Simple Hold Queue

Every submitted case lands in a "Pending Review" tab in the admin dashboard. Admin reads it, ticks a checklist (documents present, story consistent, contact details valid), then either approves it — which fires the Embassy email — or sends it back to the volunteer with a note.

Strengths

  • Simplest to build (1–2 days)
  • No new dependencies
  • Full admin control

Trade-offs

  • Admin does all the work manually
  • No data collected for Phase 2 AI
B

AI-Assisted Queue Recommended

After submission, Claude reviews the case and generates a brief pre-screening note for the admin: "Narrative consistent with case type. Employer name missing. No document attached." The admin sees the AI's notes first, then approves or returns. Every admin decision is logged — this is Phase 2's training data.

Strengths

  • Admin gets a head start — faster reviews
  • Catches things tired admins miss
  • Every decision = labeled data for the AI agent
  • Seamless upgrade path to Phase 2

Trade-offs

  • Adds Claude API call per case
  • ~3–4 days to build
C

Tiered Auto-Routing

Urgent case types (Death, Missing Person, Police Detention) bypass the queue entirely and go straight to the Embassy — seconds matter. All other cases go to the admin queue for review. The AI screens non-urgent cases only.

Strengths

  • Embassy gets critical cases instantly
  • Queue only handles lower-urgency cases
  • Right balance of speed vs. quality

Trade-offs

  • Most complex routing logic
  • Risk: urgent cases may still have bad data
Phase 2 upgrade path (1–2 years from now): Replace the AI pre-screening note with an AI decision. If confidence is high → auto-approve. If low → still goes to admin. The admin's 1–2 years of logged decisions are what trains that confidence threshold.
